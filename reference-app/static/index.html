A collaboration backend with product surfaces, not just sockets.

OpenRTC is shaped around the things SaaS teams ship: collaborative canvases, dashboards, docs, editor comments, notification inboxes, and room-scoped permissions.

Live rooms, presence, cursors, and events

Room handles expose presence snapshots, cursor state, reconnect behavior, active-user reads, and broadcast events with traceable fan-out.

  • JSON WebSocket room lifecycle with scoped JWT authorization.
  • Ephemeral presence separated from durable document state.
  • Delivery ACK cursors and bounded event catch-up for reconnects.

Typed storage

LiveObject, LiveList, and LiveMap envelopes sit on top of durable JSON documents, optimistic mutations, conflict repair, and local undo/redo.

Comments

Durable room threads, replies, read state, metadata filters, mentions, reactions, and an embeddable React comments panel.

Yjs and rich text

Persisted binary sync, awareness over presence, compaction workers, offline cache hooks, and host-owned Tiptap, Lexical, and BlockNote controllers.

Ops by default

Local JWKS, seeded rooms, socket inspection, storage/Yjs probes, reconnect drills, stable errors, rate limits, and health metrics.

Why OpenRTC exists when managed collaboration clouds already do.

Managed services are excellent when collaboration is a feature. OpenRTC is for teams where collaboration becomes infrastructure, and the room, document, permission, retention, and deployment model must be owned.

Keep realtime control close to your product and data boundaries.

Tenant control

Room IDs, default grants, user grants, group grants, and scoped tokens are explicit instead of hidden behind a hosted tenant model.

Inspectable runtime

Socket state, admission caps, event ACKs, storage sequences, Yjs metadata, and crash drills are visible in local tooling.

OSS extensibility

The Go runtime, TypeScript SDKs, React hooks, Yjs provider, and compactor are repo-owned pieces you can audit and adapt.

Deployment choice

Run the same image as runtime or admin, use embedded local storage for dev, and Redis-backed cluster mode when you need fan-out.

Designed around rooms as the unit of trust and motion.

The runtime keeps live sockets fast while durable product state stays explicit: room records, storage documents, comments, inbox notifications, Yjs updates, and operational probes each have their own contract.

openrtc-runtime

Realtime coordinator

Owns WebSocket traffic, room membership, presence, publish fan-out, JSON storage messages, Yjs upgrades, rate limits, origin checks, and admission control.

openrtc-admin

Durable product API

Manages room metadata, access grants, active users, storage documents, threads, comments, inbox notifications, subscription settings, webhooks, stats, and health endpoints.

@openrtc/react

Application surface

Gives React teams room providers, presence hooks, cursors, avatar stacks, storage selectors, mutation hooks, comments UI, and room subscription controls.

@openrtc/yjs

Document sync lane

Provides binary Yjs sync, state-vector diffs, awareness bridging over presence, optional IndexedDB cache, reconnect diagnostics, and trusted compaction support.

Where OpenRTC sits against realtime products.

This is not a claim that one tool beats every other tool. It is the deployment and ownership line: choose managed clouds for speed, channel platforms for generic pub/sub, database realtime for data feeds, and OpenRTC when collaboration itself is part of your infrastructure.

Product shape Best fit Collaboration surface Ownership model OpenRTC difference
Liveblocks Fastest path to managed collaborative products. Multiplayer editing, comments, notifications, storage, Yjs/editor integrations, and UI packages. Hosted collaboration cloud. OpenRTC mirrors the room/presence/storage/comments shape while keeping runtime, admin API, storage contracts, and deployment in your repo.
Ably Global realtime messaging, chat, spaces, live state, and pub/sub infrastructure. Strong realtime primitives with collaboration products layered on channels. Managed realtime platform. OpenRTC is narrower and product-opinionated around SaaS rooms, access grants, comments, typed storage, and Yjs persistence.
Pusher Channels Broad WebSocket pub/sub, presence channels, dashboards, webhooks, and fallback transport. Events and presence, but app teams build durable comments, storage, and editor sync themselves. Managed channel service. OpenRTC pairs live channels with durable room APIs, SDK materializers, and local dev probes.
Supabase Realtime Broadcast, presence, and Postgres change streams inside the Supabase ecosystem. Realtime data and presence primitives for apps that already use Supabase or Postgres feeds. Managed Supabase service with open-source components. OpenRTC focuses on collaboration rooms, typed storage, threads, notifications, and Yjs rather than database-change delivery.
DIY Yjs + Redis Maximum control when a team can design every protocol and product API. Document sync can be excellent, but comments, notifications, auth, observability, and limits are custom work. Fully owned stack. OpenRTC gives the owned-stack path a product contract, SDKs, tests, local console, and operational guardrails.

Current external product positioning was checked against official docs for Liveblocks, Ably, Pusher Channels, and Supabase Realtime while this page was built.

OpenRTC gives teams a collaboration layer they can own without turning every product squad into protocol engineers.
